## 2. 비밀 키 노출 검색

- 원칙: **브라우저에 올라가는 파일에는 공개용 키만.** 웹 페이지 소스는 누구나 열람 가능
- 허용: Supabase publishable 키(`sb_publishable_…`) 또는 anon 키 — RLS(행 수준 보안) 정책이 켜진 테이블에서만
- 금지: Supabase secret 키(`sb_secret_…`) · service_role 키 · GitHub 토큰(`ghp_` · `github_pat_`) · 각종 API 비밀 키 · 비밀번호

Claude Code에 요청 예:

> 이 저장소 전체에서 비밀 키나 토큰처럼 보이는 문자열 찾아 줘. sb_secret_, service_role, ghp_, github_pat_, sk-, password, secret 포함 여부와 파일·줄 번호로 보고해 줘. 고치지는 말고 목록만.

직접 검색 명령 (Git Bash):

```
git grep -n -i -E "sb_secret_|service_role|ghp_|github_pat_|sk-[A-Za-z0-9]|password|secret"
```

- 검색 결과가 주석·설명 문장뿐인지 한 줄씩 확인
- 이미 커밋·푸시한 키 = 삭제 커밋만으로는 이력에 남음 → **해당 키 즉시 폐기·재발급**(Supabase 대시보드·GitHub 설정) 후 새 키 사용

## 3. 원본 데이터 공개 여부 판단

GitHub Pages 공개 저장소 = 인터넷 누구나 열람·다운로드 가능.

| 질문 | 예 → 조치 |
|---|---|
| 실제 회사 생산·불량·원가·단가 데이터인가 | 저장소 제외. 집계 결과만 페이지에 넣거나 가상 데이터로 대체 |
| 고객사 이름·클레임 내용이 있는가 | 제외 또는 익명화("고객사 A") |
| 직원 이름·근무 조 편성 등 사람 정보가 있는가 | 제외 또는 "작업자A" 형식 |
| 교육용 가상 데이터인가 (예: (가상) 동백정밀) | 공개 가능. README에 "가상 데이터" 명시 |
| 판단이 어려운가 | 공개하지 않음 → 팀장·보안 담당 확인 후 결정 |

- 사내 실데이터 프로젝트 = 비공개 저장소(`--private`) 사용. 단, GitHub 무료 요금제의 Pages = 공개 저장소 대상 → 비공개 배포는 유료 요금제·사내 서버 검토 (요금제 조건은 GitHub 안내 확인)
- `.gitignore` 예: `원본/` · `*.xlsx` · `.env`

## 4. README.md 필수 항목

- 제목 · 한 줄 설명 (무엇을 보여 주는 페이지인가)
- 배포 주소
- 사용 방법 (버튼·필터·입력 방법)
- 데이터 출처 · 기간 · "교육용 가상 데이터" 여부
- 계산식 출처 (예: `참고/KPI_정의서.md`)
- 만든 도구 (Claude Code 등) · 만든 사람(팀명) · 날짜
- 알려진 한계 · 개선 예정 (이슈 번호 연결)

## 6. 배포 후 (인터넷 주소)

| # | 항목 | 확인 방법 | 결과 |
|---:|---|---|---|
| 14 | **주소 열림** | `https://<아이디>.github.io/<이름>/` 접속 → 404 아님 | |
| 15 | **새로고침** | Ctrl+F5(강력 새로고침) 후에도 최신 내용 표시. 옛 화면이면 몇 분 뒤 재확인 | |
| 16 | **모바일 폭** | 휴대폰으로 접속 또는 F12 → 기기 모드 390px · 가로 스크롤 없음 · 글자·버튼 겹침 없음 | |
| 17 | **콘솔 오류** | 배포 주소에서 F12 → Console 빨간 줄 0건 (로컬에서 없던 오류 = 경로·대소문자 문제 의심) | |
| 18 | 외부 라이브러리 로드 | 차트·DB 연결 정상 (Network 탭에서 빨간 요청 없음) | |
| 19 | 비밀 키 재확인 | 배포 페이지에서 Ctrl+U(소스 보기) → Ctrl+F `secret` · `service_role` 0건 | |
| 20 | 개인정보 재확인 | 화면·소스에 실명·연락처 없음 | |
| 21 | 다른 사람 PC에서 열림 | 팀원에게 주소 공유 → 같은 화면 확인 | |
| 22 | 자동 점검 (선택) | Claude in Chrome: 주소 열기 → 버튼·폼 입력 → 결과 확인 = 사람 대신 E2E 점검 | |
| 23 | **이슈 등록** | 발견한 문제·개선 요청 = `gh issue create --title "..." --body "..."` · 목록 `gh issue list` | |

## 7. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 404 | 반영 대기 시간 · `index.html` 이름·위치 · Pages 켜기 여부 |
| 화면은 뜨는데 차트·이미지 없음 | 상대 경로 · 파일명 대소문자(웹 서버는 구분) · CDN 주소 |
| 로컬과 다른 옛 화면 | 브라우저 캐시 → Ctrl+F5 · 몇 분 뒤 재확인 |
| 비밀 키를 올려 버림 | 키 즉시 폐기·재발급 → 코드에서 제거 → 커밋 → 이슈로 기록 |
| 이전 버전으로 되돌리기 | `git log --oneline` → `git revert <커밋>` → `git push` |
