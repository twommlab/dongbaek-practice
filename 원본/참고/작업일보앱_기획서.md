# 작업일보 입력 웹앱 기획서 — (가상) 동백정밀

> 5차시 실습 레퍼런스. 이 문서를 Claude Code 에 주고 "이 기획서대로 만들어줘"로 시작.
> 테이블·보안 정책 = `참고/작업일보_테이블.sql`. 목록값 출처 = `원본/생산실적_2026Q3.xlsx` 설비마스터·품목마스터 시트, `원본/설비가동_2026Q3.xlsx` 정지사유 열.
> 교육용 가상 회사·가상 데이터. 실존 기업·인물과 무관.

## 1. 목적

- 조 종료 시 종이 작업일보 → 엑셀 재입력 → 취합 메일의 3단계를 웹 입력 1단계로 축소
- 입력 즉시 DB(Supabase) 저장 → 사무실에서 같은 화면으로 오늘 실적·불량·비가동 확인
- 입력 단계에서 오류 차단: 없는 설비·품번, 불량 > 생산, 정지사유 누락 (2차시 정제 실습의 오류 유형을 입력 시점에 예방)

## 2. 사용자

| 사용자 | 하는 일 | 기기 |
|---|---|---|
| 현장 조장(주간·야간) | 조 종료 시 설비·품번별 1건씩 입력 | 휴대폰(세로 화면) |
| 생산관리 담당 | 오늘 목록·합계 확인, 이상 건 문의 | 사무실 PC |
| 관리자(강사·팀장) | 잘못 입력된 행 정정·삭제 (Supabase 대시보드) | PC |

- 로그인 없음(실습 범위). 작성자 = 이름 대신 사번 또는 이니셜 (공개 주소에서 누구나 조회 가능하므로)

## 3. 화면

한 페이지(단일 HTML 파일)에 3개 영역. 휴대폰 폭(390px)에서 세로 1열, PC 폭에서 입력 폼 왼쪽 · 목록 오른쪽.

### 3-1. 입력 폼

- 순서: 일자 → 조 → 라인 → 설비 → 품번 → 생산수량 → 불량수량 → 비가동(분) → 정지사유 → 작성자 → 비고
- 연동 선택: 라인 선택 → 그 라인 설비만 표시 → 설비 선택 → 그 설비 생산품번만 표시
- 일자 기본값 = 오늘(한국 시간). 최근 7일 ~ 오늘만 선택 가능
- 비가동 0분 → 정지사유 '없음' 자동 선택 / 1분 이상 → '없음' 선택 불가
- 저장 버튼 → 검증 통과 시 저장 → "저장 완료" 안내 + 목록·합계 즉시 갱신 → 수량 칸만 비우고 일자·조·라인·작성자 유지(연속 입력)
- 검증 실패 → 해당 칸 아래 빨간 안내 문구, 저장 안 함

### 3-2. 오늘 목록

- 선택한 일자의 입력 건을 최신 순으로 표시
- 열: 입력 시각 · 조 · 설비 · 품번(품명) · 생산 · 불량 · 불량률 · 비가동 · 정지사유 · 작성자
- 불량률 3.0% 이상 행 = 강조 표시 (실습용 경고 기준값 · 현장 기준으로 조정 가능)
- 입력 0건 → "아직 입력 없음" 안내

### 3-3. 간단 합계

- 선택 일자 전체: 생산수량 합 · 불량수량 합 · 불량률(Σ불량 ÷ Σ생산, 소수점 1자리) · 비가동 합(분) · 입력 건수
- 계산 규칙 = `참고/KPI_정의서.md` (합계 먼저, 비율 나중 · 분모 0이면 '-')
- 라인별 소계(선택): 라인 3개 각각 생산·불량·불량률

### 3-4. 설정 필요 상태

- 페이지 맨 위 상수 `SUPABASE_URL` · `SUPABASE_PUBLISHABLE_KEY` 가 예시값 그대로이면 → "설정 필요" 안내 상자 표시, 저장 버튼 비활성
- 안내 내용: 값 확인 위치(Supabase 대시보드 프로젝트 설정 · 당일 화면 기준) · publishable 키만 사용 · secret 키 금지

## 4. 필드

테이블 `public.work_log`. 1행 = 일자·설비·조·품번 1건 (생산실적 파일 1행과 같은 단위).

| 열 | 한글 라벨 | 타입 | 필수 | 규칙 |
|---|---|---|:---:|---|
| id | 번호 | bigint (자동 증가) | 자동 | 서버가 채움. 입력 불가 |
| work_date | 일자 | date | O | 최근 7일 ~ 오늘(한국 시간) |
| line | 라인 | text | O | 프레스1라인 · 가공2라인 · 조립3라인 |
| machine | 설비 | text | O | 선택한 라인의 설비만 (표 5-1) |
| shift | 조 | text | O | 주간 · 야간 |
| part_no | 품번 | text | O | 선택한 설비의 생산품번만 (표 5-1) |
| produced_qty | 생산수량 | integer | O | 0 ~ 10,000 정수 |
| defect_qty | 불량수량 | integer | O | 0 이상 정수 · 생산수량 이하 |
| downtime_min | 비가동(분) | integer | O | 0 ~ 480 정수 (조당 계획가동 480분) |
| stop_reason | 정지사유 | text | O | 없음 · 금형교체 · 고장 · 자재대기 · 품질점검 / 비가동 0분 ⇔ 없음 |
| note | 비고 | text | - | 200자 이하 |
| writer | 작성자 | text | O | 공백 제외 1~20자 · 사번 또는 이니셜 |
| created_at | 입력 시각 | timestamptz | 자동 | 서버 시각(now()). 입력 불가 |

## 5. 검증 규칙

화면(브라우저)과 DB(체크 제약·RLS) 양쪽에 같은 규칙. 화면 검증 = 친절한 안내, DB 검증 = 최종 방어선(화면 코드를 우회한 요청도 차단).

### 5-1. 목록값 (설비마스터 · 품목마스터)

| 라인 | 설비 | 이론CT(초) | 생산품번 |
|---|---|---:|---|
| 프레스1라인 | PR-01 | 10 | DB-BR-101 브래킷A · DB-BR-102 브래킷B |
| 프레스1라인 | PR-02 | 12 | DB-CV-201 커버 · DB-BR-101 브래킷A |
| 가공2라인 | CN-01 | 40 | DB-HS-301 하우징 · DB-FL-501 플랜지 |
| 가공2라인 | CN-02 | 42 | DB-SH-401 샤프트 · DB-HS-301 하우징 |
| 가공2라인 | CN-03 | 38 | DB-FL-501 플랜지 · DB-SH-401 샤프트 |
| 조립3라인 | AS-01 | 45 | DB-AS-601 브래킷 어셈블리 · DB-AS-602 하우징 어셈블리 |
| 조립3라인 | AS-02 | 48 | DB-AS-602 하우징 어셈블리 · DB-AS-601 브래킷 어셈블리 |

- 정지사유 5종 = 설비가동 파일 `정지사유` 열 값 그대로

### 5-2. 규칙 목록

| # | 규칙 | 화면 안내 문구 예 | DB 제약 이름 |
|---:|---|---|---|
| 1 | 필수 항목 빈칸 불가 | "생산수량 입력 필요" | not null |
| 2 | 라인-설비 짝 일치 | "가공2라인 설비만 선택 가능" | work_log_line_machine_chk |
| 3 | 설비-품번 짝 일치 | "CN-02 생산품번 아님" | work_log_machine_part_chk |
| 4 | 수량·분 = 0 이상 정수 | "0 이상 정수 입력" | work_log_produced_chk · work_log_downtime_chk |
| 5 | 불량수량 ≤ 생산수량 | "불량이 생산보다 많음" | work_log_defect_chk |
| 6 | 비가동 0 ~ 480분 | "조당 최대 480분" | work_log_downtime_chk |
| 7 | 비가동 0분 ⇔ 정지사유 없음 | "비가동 있으면 정지사유 선택" | work_log_stop_pair_chk |
| 8 | 일자 = 최근 7일 ~ 오늘 | "미래·8일 이전 일자 입력 불가" | RLS 정책 work_log_insert |
| 9 | 작성자 1~20자 · 비고 200자 이하 | "작성자 입력 필요" | work_log_writer_chk · work_log_note_chk |

- 경고(저장은 허용): 불량률 10% 초과 · 생산수량 > (480 − 비가동) × 60 ÷ 이론CT (조 전체를 그 품번만 최고 속도로 돌려도 불가능한 수량) → "입력값 재확인" 확인창

## 6. 보안

| 항목 | 기준 |
|---|---|
| 페이지에 넣는 키 | publishable 키(예전 이름 anon 키)만 |
| 금지 키 | secret 키(예전 이름 service_role 키) — RLS 무시, 전체 수정·삭제 가능 |
| RLS | 반드시 켬 (`enable row level security`). 꺼져 있으면 publishable 키로도 전체 수정·삭제 가능 |
| 허용 동작 | 조회(SELECT) · 추가(INSERT)만 |
| 수정·삭제 | 정책 없음 → 불가. 정정 = 새 행 입력 + 비고에 "정정: 원 입력 시각 hh:mm" · 잘못된 행 삭제 = 관리자가 대시보드에서 |
| 서버 채움 열 | id · created_at (열 권한으로 직접 입력 차단) |
| 개인정보 | 작성자 = 사번·이니셜. 실명·연락처 입력 금지 (공개 주소 조회 가능) |
| 점검 | 적용 후 Supabase MCP `get_advisors` 보안 경고 0건 · Claude in Chrome 으로 폼 입력 E2E |

## 7. 기술 조건

- 단일 HTML 파일(`결과/작업일보앱.html`). 빌드 단계 없음
- supabase-js = CDN 주소에 정확한 버전 고정 (예: `@supabase/supabase-js@2.117.3`)
- 파일 맨 위 설정 상수 2개: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`
- 인터넷 끊김·CDN 실패 시 화면 깨지지 않고 "연결 실패" 안내
- GitHub Pages 배포 → `참고/웹배포_체크리스트.md` 점검

## 9. 금지 사항

- secret(service_role) 키를 HTML·JS·저장소·캡처·채팅에 넣기
- RLS 끄기, `using (true)` 수정·삭제 정책 추가
- 실습 전용이 아닌 프로젝트(실제 회사 DB)에 연결
- 실명·연락처·주민번호 등 개인정보 입력
- 원본 엑셀 수정 (적재는 읽기만)
- 목록값을 기획서·데이터와 다르게 임의 추가 (새 설비·품번은 설비마스터 갱신 후)
